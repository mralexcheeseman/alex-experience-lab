# Candidate Specimen Batch 01

Status: built for review; **not approved**.

Base:
`specimens-user-references-001`

Purpose:
Convert the first five reference deconstructions into the smallest testable mechanics.

## 003 — Hero Object Framing
Derived from:
ORYZO AI.

Tests:
Can an ordinary object gain perceived value from scale, restraint, framing and controlled pointer response?

Keep if:
The object feels meaningful before we add visual noise.

Kill if:
It reads as generic "premium product" styling.

## 004 — Chapter Interaction Engine
Derived from:
The Symphony of Vines.

Tests:
Can four distinct chapters use different visual responses while preserving one interaction grammar: select chapter + press/hold?

Keep if:
Variation feels coherent.

Kill if:
It feels like four unrelated effects.

## 005 — Editorial Release System
Derived from:
Shopify Editions Spring ’26.

Tests:
Can one surface hold hero, feature and update information at radically different weights without becoming a generic card grid?

Keep if:
Scanning feels obvious and density feels controlled.

Kill if:
The hierarchy is technically clear but visually dull.

## 006 — Navigable Micro-World
Derived from:
Bruno Simon.

Tests:
Can movement replace menu clicks when there are only two destinations and an obvious reset?

Keep if:
Movement is immediately understandable and enjoyable.

Kill if:
The mechanic creates friction without adding value.

## 007 — Data → Geometry Explorer
Derived from:
Every Neuron.

Tests:
Can structured data power both a guided story and a free-exploration state?

Important:
This candidate uses synthetic data solely to test the interaction model. The Every Neuron lesson is strongest when geometry corresponds to real data; do not confuse this mechanic test with a finished data-visualisation direction.

Keep if:
Guided → explorer feels substantially clearer than dropping the user directly into a node field.

Kill if:
It collapses into generic particle/network visualisation.

# Review fields

For each candidate:
- KEEP / MAYBE / KILL
- What is genuinely interesting?
- What feels generic?
- What needs to remain faithful?
- What should be reinterpreted?
- Does it belong in the eventual design language?
- Could this solve a real website/product problem?
